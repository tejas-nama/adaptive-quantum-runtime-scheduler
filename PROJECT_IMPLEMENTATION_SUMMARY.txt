1. EXECUTIVE SUMMARY & PURPOSE
================================================================================
The objective of the broader project is to design and evaluate an Adaptive
CPU-GPU Runtime Scheduler for stabilizer (Clifford) quantum circuit simulation.
The eventual scheduler will dynamically decide whether quantum circuit tasks
should run on CPU, GPU, or Hybrid CPU+GPU based on workload characteristics
(qubit count, circuit depth, measurement density, and shot count).

Per the foundational HPC methodology:
"First complete the serial code and FIND HOTSPOTS. Then parallelize them."

This milestone implements the PURE SERIAL BASELINE in Python:
- Strictly serial execution (one gate at a time, one shot at a time).
- NO parallelization, NO OpenMP, NO multithreading, NO multiprocessing.
- NO CUDA, NO OpenCL, NO GPU acceleration, NO adaptive scheduling logic.
- Natural computational structure preserved so that profiling yields true hotspots.
- Every prospective optimization site annotated with "# TODO (Optimization):".

2. CORE STABILIZER TABLEAU DATA STRUCTURE (simulator/tableau.py)
================================================================================
The simulator state uses the canonical Aaronson & Gottesman (2004) binary
tableau representation of dimension (2n + 1) x (2n + 1) for an n-qubit register.

A. Row Layout:
   - Rows 0 to n - 1 (Destabilizers R_0, ..., R_{n-1}):
     Independent Pauli operators that complete the symplectic basis.
   - Rows n to 2n - 1 (Stabilizers R_n, ..., R_{2n-1}):
     The n commuting Pauli generators that uniquely define the quantum state
     (|psi> is the unique +1 eigenstate: R_{n+i} |psi> = +|psi>).
   - Row 2n (Scratch Row):
     Dedicated row for evaluating deterministic measurement phases without
     modifying the active stabilizer state.

B. Column Layout:
   Each row represents a Pauli operator R_i = (-1)^{r_i} * prod_{j=0}^{n-1} P_{i, j}.
   - Binary matrix X of shape (2n + 1, n):
     x[i, j] = 1 if P_{i, j} has an X or Y component; 0 otherwise.
   - Binary matrix Z of shape (2n + 1, n):
     z[i, j] = 1 if P_{i, j} has a Z or Y component; 0 otherwise.

   Mapping:
     (x=0, z=0) -> Identity (I)
     (x=1, z=0) -> Pauli-X   (X)
     (x=0, z=1) -> Pauli-Z   (Z)
     (x=1, z=1) -> Pauli-Y   (Y = i*X*Z)

C. Phase Vector r of shape (2n + 1,):
   - r[i] = 0 -> Sign factor +1
   - r[i] = 1 -> Sign factor -1

D. Initial Ground State (|00...0>):
   - Destabilizers initialized to X_i: x[i, i] = 1, z[i, :] = 0, r[i] = 0.
   - Stabilizers initialized to Z_i:   z[n+i, i] = 1, x[n+i, :] = 0, r[n+i] = 0.

E. In-Place Pauli Row Multiplication (row_mult(h, i)):
   Computes R_h <- R_h * R_i.
   Uses Aaronson & Gottesman g(x1, z1, x2, z2) function for phase tracking:
     g(0,0, x2,z2) = 0
     g(1,1, x2,z2) = z2 - x2
     g(1,0, x2,z2) = z2 * (2*x2 - 1)
     g(0,1, x2,z2) = x2 * (1 - 2*z2)
   Exponent of i: E = (2*r[h] + 2*r[i] + sum_{j=0}^{n-1} g(x_hj, z_hj, x_ij, z_ij)) mod 4.
   Since products in the stabilizer group have eigenvalues +/- 1, E in {0, 2}:
     r[h] <- 1 if E == 2 else 0.
   Updates Pauli coordinates: x[h, j] ^= x[i, j], z[h, j] ^= z[i, j].

3. CLIFFORD GATES IMPLEMENTED (simulator/gates.py)
================================================================================
All gates are Clifford group unitaries that map Pauli operators to Pauli
operators via unitary conjugation. Each gate updates rows 0 to 2n - 1:

1. Hadamard Gate (H) on qubit q:
   Conjugation: H X H^dag = Z,  H Z H^dag = X,  H Y H^dag = -Y
   Tableau update for each row i:
     r[i] ^= (x[i, q] * z[i, q])
     x[i, q], z[i, q] = z[i, q], x[i, q] (swap)

2. Phase Gate (S) on qubit q:
   Conjugation: S X S^dag = Y,  S Z S^dag = Z,  S Y S^dag = -X
   Tableau update for each row i:
     r[i] ^= (x[i, q] * z[i, q])
     z[i, q] ^= x[i, q]

3. Controlled-NOT Gate (CNOT / CX) from control c to target t:
   Conjugation:
     X_c -> X_c * X_t,  Z_t -> Z_c * Z_t,  Y_c * Y_t -> - X_c * Z_t
   Tableau update for each row i:
     r[i] ^= x[i, c] * z[i, t] * (x[i, t] ^ z[i, c] ^ 1)
     x[i, t] ^= x[i, c]
     z[i, c] ^= z[i, t]

4. Pauli-X Gate (X) on qubit q:
   Conjugation: X Z X = -Z,  X Y X = -Y,  X X X = X
   Tableau update: r[i] ^= z[i, q]

5. Pauli-Y Gate (Y) on qubit q:
   Conjugation: Y X Y = -X,  Y Z Y = -Z,  Y Y Y = Y
   Tableau update: r[i] ^= (x[i, q] ^ z[i, q])

6. Pauli-Z Gate (Z) on qubit q:
   Conjugation: Z X Z = -X,  Z Y Z = -Y,  Z Z Z = Z
   Tableau update: r[i] ^= x[i, q]

7. Controlled-Z Gate (CZ) between qubits c and t:
   Conjugation: X_c -> X_c * Z_t,  X_t -> Z_c * X_t
   Tableau update for each row i:
     r[i] ^= x[i, c] * x[i, t] * (z[i, c] ^ z[i, t])
     z[i, c] ^= x[i, t]
     z[i, t] ^= x[i, c]

4. COMPUTATIONAL BASIS MEASUREMENT (simulator/measurement.py)
================================================================================
Measures a single qubit in the Z-basis according to Aaronson & Gottesman (2004):

Step 1: Check for Anti-Commuting Stabilizer Generator:
  Scan rows p in [n, 2n - 1]. If x[p, qubit] == 1, stabilizer R_p anti-commutes
  with Z_qubit.

Branch A: Random (Projective) Measurement (Anti-commuting stabilizer p found):
  - Outcome is fundamentally random (0 with 50%, 1 with 50%).
  - Sample outcome v in {0, 1} via random generator.
  - Gaussian Elimination Pivot:
    For all other rows i in [0, 2n - 1] (i != p) where x[i, qubit] == 1:
      row_mult(i, p)   (cancels out the X component on qubit in all other rows)
  - Replace destabilizer p - n with old stabilizer row p.
  - Set stabilizer row p to (-1)^v * Z_qubit:
      x[p, :] = 0, z[p, :] = 0, z[p, qubit] = 1, r[p] = v.
  - Return v.

Branch B: Deterministic Measurement (All stabilizers commute with Z_qubit):
  - The state is already an eigenstate of Z_qubit; the outcome is deterministic.
  - Clear scratch row 2n: x[2n, :] = 0, z[2n, :] = 0, r[2n] = 0.
  - For each destabilizer i in [0, n - 1]:
      If x[i, qubit] == 1:
        row_mult(2n, n + i)  (multiply scratch by corresponding stabilizer n+i)
  - The measurement result is r[2n] (0 or 1).
  - The active tableau state is preserved without modification.
  - Return r[2n].

5. IMPLEMENTED QUANTUM CIRCUITS & WORKLOADS (circuits/)
================================================================================
Six distinct categories of quantum circuits were implemented to benchmark and
profile the simulator across diverse algorithmic regimes:

1. Single-Qubit Hadamard Circuit (circuits/basic.py):
   Structure: q0: --[H]--[M]--
   Expected Outcome: |0> ~50%, |1> ~50%.

2. Two-Qubit Bell State |Phi+> (circuits/basic.py):
   Structure:
     q0: --[H]--*----[M]--
                |
     q1: -------X----[M]--
   Expected Outcome: |00> ~50%, |11> ~50%, strictly 0% for |01> and |10>.

3. Multi-Qubit Greenberger-Horne-Zeilinger (GHZ) State (circuits/basic.py):
   Structure for n qubits:
     H(0) followed by a chain of CNOT(i, i+1) for i = 0 to n - 2,
     followed by measurements on all n qubits.
   Expected Outcome: Equal superposition of |00...0> and |11...1>.
   Validated for n = 3, 5, 10, 50 qubits.

4. Configurable Random Clifford Circuits (circuits/random_clifford.py):
   Parameters: num_qubits, circuit_depth, random_seed, gate_set, measurements.
   In each depth cycle:
     - Single-qubit gates (H, S, or idle) randomly chosen across qubits.
     - Disjoint qubit pairs randomly chosen for two-qubit CNOT (or CZ) gates.
   Configurable up to 100+ qubits and 1,000+ depth.
   Fully deterministic and reproducible with fixed pseudo-random seeds.

5. Measurement-Heavy Workloads (circuits/measurement_heavy.py):
   Models active quantum circuits and quantum error correction syndrome cycles.
   Structure:
     Repeated cycles of a burst of Clifford gates (H, S, CNOT) followed by
     mid-circuit measurements on a random fraction (e.g., 40-50%) of qubits.
   Triggers repeated alternation between unitary updates and Gaussian
   elimination / scratch row reduction.

6. Quantum Error Correction (QEC) Circuits (circuits/qec.py):
   A. 3-Qubit Bit-Flip Code:
      - 3 data qubits (d0, d1, d2) + 2 syndrome ancilla qubits (a0, a1).
      - Encoding: CNOT(d0, d1), CNOT(d0, d2) prepares |000>.
      - Error injection: Pauli-X on specified data qubit (None, 0, 1, or 2).
      - Syndrome extraction:
        * Stabilizer S1 = Z0 * Z1 measured via CNOT(d0, a0), CNOT(d1, a0) -> c0
        * Stabilizer S2 = Z1 * Z2 measured via CNOT(d1, a1), CNOT(d2, a1) -> c1
      - Syndrome output mapping:
        * No error -> '00'
        * Error on d0 -> '10'
        * Error on d1 -> '11'
        * Error on d2 -> '01'
   B. Repetition Code Multi-Round Syndrome Extraction:
      - Configurable data qubits and extraction rounds.
      - Measures nearest-neighbor Z_d * Z_{d+1} parity checks across rounds.

6. SIMULATOR ENGINE & MULTI-SHOT ARCHITECTURE (simulator/simulator.py)
================================================================================
The Simulator class coordinates circuit execution:
- run_shot(circuit):
  Allocates a fresh StabilizerTableau(n) and executes each GateOperation
  sequentially:
    for op in circuit.operations:
      if op.is_measurement():
        measure_qubit(tableau, op.qubits[0])
      else:
        CLIFFORD_GATES[op.name](tableau, *op.qubits)
- simulate(circuit, shots, seed):
  Sequentially loops over shots:
    for shot in range(shots):
      record = run_shot(circuit)
  Collects counts dictionary, raw bitstring list, and timings using
  time.perf_counter().
- Circuit class (simulator/circuit.py) provides:
  * Fluent builder API: c.h(0).s(1).cnot(0, 1).measure(0)
  * Properties: num_gates, num_measurements, depth
  * to_stim(): automatic conversion to Stim circuits for cross-validation.

11. ROADMAP: FUTURE PARALLELIZATION & ADAPTIVE SCHEDULING (PHASES 2-4)
================================================================================
Based on the empirical profiling findings from this baseline milestone:

PHASE 2: CPU PARALLELIZATION
- Target 1: Clifford gate row updates (apply_cnot, apply_h, apply_s).
  Map the independent 2n row updates to OpenMP multi-threaded CPU loops.
- Target 2: Row multiplication (row_mult).
  Implement 64-bit SIMD bit-packing (AVX2/AVX-512) reducing inner-loop operations
  by a factor of 64.
- Target 3: Multi-shot batching.
  Distribute independent shots across CPU cores.

PHASE 3: GPU ACCELERATION (QuaSARQ-INSPIRED)
- Target 1: Massively parallel Clifford gate CUDA kernels updating thousands of
  tableau elements simultaneously.
- Target 2: Data-parallel Gaussian elimination primitives for measurement updates.
- Target 3: Multi-shot GPU grid execution: launching thousands of independent
  shots across GPU thread blocks.

PHASE 4: ADAPTIVE CPU-GPU RUNTIME SCHEDULER
